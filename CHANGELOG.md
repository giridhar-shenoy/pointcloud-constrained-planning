## [0.2.0] - 2026-10-31

v0.2 plans the v0.1 queries a second time with a pipeline written directly on OMPL,
Pinocchio/coal and a trapezoidal time parameterisation, and compares it with MoveIt 2 on the same
queries, scene, settings and controller (built 29 Oct, merged as b9e3d19, ee232d7 and 2f4f95d).
The README was then rewritten for readers and corrected after an external review and a second full
regeneration on 31 Oct.

### Added

- `pcp_direct` (C++17): a second planning pipeline written directly on the libraries.
  - Collision checker: Pinocchio model + coal collision meshes from the same `robot_description`,
    the shelf boxes as coal boxes, `addAllCollisionPairs` minus the SRDF's disabled pairs. It
    tests the same 62 pairs as MoveIt's OMPL validity checker (unit-tested).
  - Planner: OMPL `SimpleSetup` + RRTConnect in `JointSpaceL1`, a `RealVectorStateSpace` with
    MoveIt's L1 joint metric and summed extent. Settings are read from
    `pcp_moveit_config/config/ompl_planning.yaml`; simplification uses MoveIt's budget rule.
  - Time parameterisation with the trapezoidal profile generator of ur5e-teaching-controllers
    (copied, see THIRD_PARTY.md) into a `JointTrajectory`; `config/joint_limits.yaml` holds the
    limits MoveIt's TOTG uses.
  - FollowJointTrajectory executor, and a tracking monitor (`/joint_states` vs the controller's
    reference) used for both pipelines.
  - `shelf_boxes_loader` (YAML → `CollisionObject`) and `collision_agreement` (MoveIt's planning
    scene vs the direct checker on seeded configurations, plus a contact-boundary probe).
  - `bench_direct`: both pipelines on the same queries, frozen box scene, settings and controller,
    with dense cross-validation by the other pipeline's checker. It records MoveIt's configured
    OMPL context, and can optionally probe MoveIt's validity-check counts.
  - Keep-upright in the direct pipeline (`KeepUprightConstraint` on OMPL's `ProjectedStateSpace`)
    and an optional octomap in the direct checker (move_group's map as one `coal::OcTree`).
- Results: `results/queries_boxes.json` (seed 0; identical to `queries.json`,
  determinism-tested), `results/collision_agreement*.csv`, `results/bench_direct.csv` (with
  execution), `results/bench_direct_upright.csv` and `results/bench_direct_octomap.csv` (plan
  only), `results/check_probe.json`, and the first full run that cascaded after one aborted
  execution in `results/runs/`.
- `results/rerun_2026-10-31/`: the CSV and JSON files of the second full regeneration (31 Oct, at
  e79d066), kept beside the committed results.
- Scripts: `collision_agreement.sh`, `bench_direct.sh` (plan-only or with Gazebo execution),
  `check_probe.sh`, `aggregate_direct.py` (+ tests).
- A generated run-to-run comparison, 30 Oct vs 31 Oct (v0.2 main metrics and v0.1 success counts
  side by side), in `docs/results.md` and, in short form, in the README's Reproducibility section.
- README sections "Reproducibility" and "What transfers to a real UR5e"; two new failure items
  (tracking error larger than the collision margin; the direct keep-upright planner failing across
  compartments).
- GIFs `docs/assets/hero.gif` (point cloud, octomap and a path through the shelf),
  `docs/assets/keep_upright.gif` and `docs/assets/direct_vs_moveit.gif`, each regenerated by
  `scripts/record_gifs.sh` with a burned-in caption (helpers in `scripts/gif/`: map capture, RViz
  rendering under xvfb, forward kinematics for the live tilt, composition); the GIF step is now
  the last step of `regenerate_all.sh`, so a failed recording can no longer stop the benchmarks.
- CI: pcp_direct gtests, collision agreement on 50 configurations in the smoke step, and a 5-query
  plan-only direct-vs-MoveIt mini-benchmark; a `workflow_dispatch` trigger.
- Docs: a second Mermaid lane in `docs/architecture.md`, the v0.2 block in `docs/results.md`, and
  the v0.2 settings, equations and the long form of every failure item in `docs/planners.md`.

### Changed

- README rewritten for three kinds of reader: one plain sentence and three short paragraphs on the
  first screen, every term defined at first use, a short headline table and a plain chart; the
  15-row v0.2 table, the per-class tables and the log-log scatter moved to `docs/results.md`, the
  settings and the long failure explanations to `docs/planners.md`. The failure items are grouped
  under five headings and numbered F1–F27; none was removed.
- Every measured number in the README is written by `scripts/aggregate.py` or
  `scripts/aggregate_direct.py`; hand-typed numbers were removed from the prose. The old
  `direct-results` README block is retired.
- The v0.2 speed-gap explanation is stated as a hypothesis (the per-check cost is measured, its
  cause is not; the broadphase ablation is next), and the keep-upright explanation was replaced by
  "cause not measured", with the finite-difference constraint Jacobian as the first suspect.
- `docs/architecture.md` prose covers v0.2; `docs/planners.md` names the benchmark planner config
  `RRTConnectRange2`.
- `pcp_benchmark` exports `pcp_benchmark_core` (additive; v0.1 outputs unchanged).
- `scripts/aggregate.py` keeps the v0.2 block in `docs/results.md` when it regenerates.
- Dockerfile installs Pinocchio, coal, OMPL and control_msgs.
- The working logs (NOTES.md, CHECKPOINTS.md, MORNING.md) are no longer tracked.

### Fixed

- `bench_direct` escapes from a colliding configuration before repositioning (the first full run
  cascaded after one aborted execution).
- MoveIt's octomap is read with `octomap_msgs::msgToMap` (MoveIt writes full, not binary, maps).
- The per-check cost row compares the cost inside both planners (the probe), not against the
  collision-agreement microbenchmark.
- The GIF recorder (`record_demo.py`, run by `scripts/record_gifs.sh`) retries an execution that
  MoveIt reports as `CONTROL_FAILED` (a path-tolerance abort in Gazebo) from the start, up to three
  attempts in all, and logs each attempt; a single abort ended the 31 Oct regeneration at the GIF
  step.
- The hero GIF is under 15 s.
- Review corrections: the v0.1 wall time is labelled per source file; the probe row of the v0.2
  table cites `results/check_probe.json` and its commit; the probe's counting of MoveIt's cached
  validity verdicts is disclosed; the repositioning counter is worded so that it does not hide a
  recovered abort; "±2π joints" corrected (the elbow is ±π).
- Dangling references to untracked or missing files (NOTES.md, SHARED.md, MACHINE.md,
  docs/controllers.md) in comments; THIRD_PARTY.md gives the copied file's path and notes that its
  source repository is private until published.

### Removed

- `docs/assets/constrained_vs_unconstrained.gif` (replaced by `keep_upright.gif`).

## [0.1.0] - 2026-10-28

MoveIt 2 (MoveItCpp, OMPL RRTConnect) on a live camera octomap of a box shelf: 100 seeded
queries with and without a keep-upright orientation constraint.

### Added

- Repository skeleton: MIT license, Dockerfile on `ros:lyrical-ros-base`, devcontainer, GitHub
  Actions CI, pre-commit (ruff, clang-format, yamllint, markdownlint), docs and scripts stubs.
- `pcp_scenes`: shelf scene as one YAML shared by the Gazebo world generator and the query
  generator, with a drift test.
- `pcp_description`: UR5e (`ur_simulation_gz`) plus a fixed Gazebo `rgbd_camera`.
- `pcp_moveit_config`: OMPL with `enforce_constrained_state_space`, PointCloudOctomapUpdater
  (2 cm, 2.0 m range, self-filter), KDL.
- `pcp_bringup`: headless `sim.launch.py`, camera bridge, smoke check and demo recorder.
- `pcp_benchmark` (C++17, MoveItCpp): keep-upright constraint builder, deterministic
  damped-least-squares query generator (`results/queries.json`, 100 queries, seed 0), runner on a
  frozen octomap snapshot, path metrics (joint/TCP length, max tilt on the densified path), gtests.
- Scripts: `with_sim.sh` (process-group teardown), `ci_smoke.sh`, `bench_planners.sh`,
  `bench_octomap_resolution.sh`, `aggregate.py` (Wilson intervals, tables, plots),
  `record_gifs.sh`, `regenerate_all.sh`.
- Results: `results/bench.csv` (RRTConnect, range 2 rad × {none, orientation} × 100 queries),
  tuning set `results/tuning/` (seed 1, 20 queries) used to choose `range`, ablation
  `results/ablation/bench_lvsf0.005.csv`.
- BiTRRT column (`results/bench_bitrrt.csv`, range chosen on the tuning set) and a 2 cm vs 5 cm
  octomap resolution sweep (`results/sweep/`).
- GIF `docs/assets/constrained_vs_unconstrained.gif` recorded from Gazebo with headless rendering.
- Docs: README, `docs/architecture.md`, `docs/planners.md`, `docs/results.md`.

### Fixed

- `longest_valid_segment_fraction` 0.005 → 0.0003: MoveIt's extent is the sum of joint ranges
  (69.1 rad for the UR5e), so 0.005 checked motions only every 0.35 rad.
- `ValidateSolution` now runs before time parameterization (TOTG blending capped at 0.01 rad), and
  executed trajectories are re-checked at 0.01 rad (`dense_collision_free`).
- Keep-upright reference yaw centred between start and goal (rotation-vector yaw/tilt coupling).
- The benchmark plans only on move_group's octomap (it had silently built a second one), receiving
  the scene on the topic MoveItCpp listens to.
- Benchmark CSVs are written atomically (`.partial`, then rename).
- `joint_trajectory_controller` is spawned with `--param-file` (it never initialized under
  ros2_control 6.10 through `ur_sim_control`).
- Benchmark node exits with `_Exit` (MoveIt 2.15.2 `~MoveItCpp` segfault), launch overrides beat
  YAML wildcards, `with_sim.sh` waits only on real `gz sim` processes.
