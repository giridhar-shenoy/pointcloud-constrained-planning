# scripts

Every number and every GIF in the top-level README comes from a script in this directory.
`regenerate_all.sh` runs all of them from scratch. If a number in the README cannot be
regenerated by a script here, it is removed from the README.

| Script | What it does | Produces |
|---|---|---|
| `with_sim.sh <cmd>` | starts `sim.launch.py` in its own process group, runs `<cmd>`, kills the whole group, fails if anything survives | — |
| `ci_smoke.sh` | sim → octomap on `/monitored_planning_scene` → one RRTConnect plan + one goal inside a board that must be rejected (240 s cap) | exit code |
| `bench_planners.sh [N] [CSV] [QUERIES] [EXTRA_YAML]` | C++ benchmark node against a live octomap | `results/bench.csv` + `.meta.json` |
| `aggregate.py` | Wilson intervals, medians/p95, per-class table, tuning/ablation sections, plots | `docs/results.md`, README results block, `results/summary.json`, `docs/assets/bench_*.png` |
| `record_gifs.sh` | re-plans one query (lowest id solved under both constraints) and records it in Gazebo | `docs/assets/constrained_vs_unconstrained.gif` |
| `regenerate_all.sh` | build, unit tests, queries.json byte-for-byte check, smoke, benchmark, aggregate, GIF | all of the above |
| `tests/` | pytest for `aggregate.py` | — |

On the shared development laptop, Gazebo scripts run under `flock ~/work/.locks/gazebo.lock`.
