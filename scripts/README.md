# scripts

Every number and every GIF in the top-level README comes from a script in this directory.
`regenerate_all.sh` runs all of them from scratch. If a number in the README cannot be
regenerated by a script here, it is removed from the README.

## v0.1: MoveIt 2 on the camera octomap

| Script | What it does | Produces |
|---|---|---|
| `with_sim.sh <cmd>` | starts `sim.launch.py` in its own process group, runs `<cmd>`, kills the whole group, fails if anything survives; waits for any other `gz sim` to exit first | — |
| `ci_smoke.sh` | sim → octomap on `/monitored_planning_scene` → one RRTConnect plan + one goal inside a board that must be rejected (240 s cap) | exit code |
| `bench_planners.sh [N] [CSV] [QUERIES] [EXTRA_YAML]` | C++ benchmark node against a live octomap | `results/bench.csv` + `.meta.json` (or the given CSV) |
| `bench_octomap_resolution.sh [N] [RES...]` | the first N evaluation queries at each octomap resolution, one simulation per resolution (defaults 20, 0.02 0.05) | `results/sweep/octomap_<res>.csv` |
| `aggregate.py` | Wilson intervals, medians/p95, per-class table, tuning/sweep/ablation sections, plots | `docs/results.md` except its v0.2 block, `results/summary.json`, `docs/assets/bench_*.png` |
| `record_gifs.sh [BENCH_CSV] [DIRECT_CSV]` | picks one query by a fixed rule (see the script header), re-plans and executes it in Gazebo while a camera records (`src/pcp_bringup/scripts/record_demo.py`), renders the point cloud, octomap and planned path in RViz under xvfb (`scripts/gif/`), and writes the GIFs with burned-in captions (needs `rviz2`, `robot_state_publisher`, `sensor_msgs_py`, `xvfb` and `xauth`, which the CI image does not install); it is the last step of `regenerate_all.sh`; an execution that MoveIt reports as `CONTROL_FAILED` (a path-tolerance abort in Gazebo) is retried from the start, up to three attempts in all, each attempt logged | `docs/assets/hero.gif`, `docs/assets/keep_upright.gif`, `docs/assets/direct_vs_moveit.gif` |

## v0.2: the direct pipeline beside MoveIt 2

| Script | What it does | Produces |
|---|---|---|
| `collision_agreement.sh [N] [CSV] [SEED]` | MoveIt's planning scene vs the direct checker on N seeded uniform configurations plus a boundary probe; no Gazebo (defaults 500, `results/collision_agreement.csv`, 0) | `results/collision_agreement.csv` + `.meta.json`, `results/collision_agreement_boundary.csv` |
| `bench_direct.sh [N] [CSV] [--plan-only] [--octomap]` | both pipelines on the same queries, scene, settings and controller; with Gazebo execution unless `--plan-only`; `--octomap` plans on move_group's camera octomap; `PCP_CONSTRAINT=orientation` adds the keep-upright constraint | `results/bench_direct.csv` + `.meta.json` (or the given CSV) |
| `check_probe.sh [N] [OUT]` | counts and times MoveIt's validity checks inside its own OMPL planning context, and the direct planner's, one query per process; no Gazebo (defaults 20, `results/check_probe.json`) | `results/check_probe.json` |
| `aggregate_direct.py` | the v0.2 tables, the run-to-run comparison against `results/rerun_2026-10-31/`, and every generated README block (they combine v0.1 and v0.2 numbers; the v0.1 ones are computed with `aggregate.py`'s functions from the same CSVs, so the two scripts run in either order) | the v0.2 block of `docs/results.md`, the README's generated blocks, `results/summary_direct.json`, `docs/assets/direct_vs_moveit_*.png` |

## Both

| Script | What it does | Produces |
|---|---|---|
| `aggregate.py --check`, `aggregate_direct.py --check` | recompute from the CSVs and exit 1 if what each script writes (its part of `docs/results.md`, its summary JSON and, for `aggregate_direct.py`, every README block) differs from the committed files; nothing is written and no plot is made | exit code |
| `regenerate_all.sh` | build, unit tests, byte-for-byte check of the query files, smoke test, every v0.1 and v0.2 benchmark, both aggregations and the GIFs | all of the above |
| `tests/` | pytest for `aggregate.py` and `aggregate_direct.py` | — |

`results/rerun_2026-10-31/` holds the CSV and JSON files of the second full regeneration on
31 Oct (at e79d066). It was two runs: `regenerate_all.sh` stopped at the GIF step on a
`CONTROL_FAILED` abort, and its remaining v0.2 steps then ran as a continuation. Those files are
inputs to the run-to-run comparison only; the published tables come from the files in `results/`.

The 0.005-resolution ablation (`results/ablation/`) is not regenerated by `regenerate_all.sh`: it
needs the commit it was run at (`git checkout 6c12eeb && scripts/bench_planners.sh 100
results/ablation/bench_lvsf0.005.csv`).

On the shared development laptop, Gazebo scripts run under `flock ~/work/.locks/gazebo.lock`, and
the timed v0.2 runs under the heavy, build and gazebo locks together (see `regenerate_all.sh`).
